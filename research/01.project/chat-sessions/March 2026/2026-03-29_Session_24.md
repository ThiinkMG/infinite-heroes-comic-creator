## Key Decisions Made

### Decision: Context Picker as Inline Dropdown (not modal)
- **Why**: Keeps the interaction close to the AI Improve button and matches the existing pattern from the "Describe Your Story" field in Setup.tsx. A separate modal would add unnecessary navigation overhead.
- **Technical Implication**: The dropdown uses local component state (`showContextDropdown`, `selectedContextChars`, `extraContext`) and is rendered inline in both the collapsed card view and the expanded modal view.
- **Alternatives Rejected**: Full modal dialog for context selection; adding context to ProfilesDialog instead.
- **Files Affected**: `components/CharacterCard.tsx`

### Decision: Use `div role="button"` for Collapsible Section Headers
- **Why**: The "1. THE CAST" and "2. THE STORY" headers are `<button>` elements that contain other interactive children (`<button>` elements for ADD CHARACTER, SURPRISE ME). `<button>` inside `<button>` is invalid HTML — browsers auto-correct this by repositioning elements, which de-syncs React's virtual DOM from the real DOM and breaks unrelated click handlers like START ADVENTURE.
- **Technical Implication**: `<div role="button">` with appropriate click handler is semantically acceptable for a container that collapses a section, as long as keyboard accessibility is also handled (tabIndex + onKeyDown).
- **Alternatives Rejected**: Refactoring the inner buttons to non-button elements (would require more widespread changes); wrapping in a non-interactive header with a separate toggle button area.
- **Files Affected**: `Setup.tsx`

### Decision: Portrait Label Changed from `<p>` to `<div>`
- **Why**: HelpTooltip renders a `<div>` internally. A `<div>` inside a `<p>` is invalid HTML (block element inside inline element). This caused another React DOM warning and potential event system interference.
- **Technical Implication**: Visual output is identical; only the semantic element type changes.
- **Files Affected**: `components/CharacterCard.tsx`

## Issues and Solutions

### Issue: Start Adventure Button Not Responding to Clicks
- **Error**: No JS error thrown — button appeared functional but clicking had no effect
- **Cause**: Two invalid DOM nesting violations caused browsers to auto-correct element positions, de-syncing React's virtual DOM from the actual DOM. This broke React's synthetic event system for the START ADVENTURE button even though the button itself was not part of the invalid nesting.
  - Violation 1: `<button>` (section header) containing `<button>` children (ADD CHARACTER, SURPRISE ME)
  - Violation 2: `<p>` (portrait label) containing `<div>` (HelpTooltip)
- **Solution**: Changed offending outer `<button>` elements to `<div role="button">` in Setup.tsx; changed portrait `<p>` to `<div>` in CharacterCard.tsx
- **Learning Logged**: Yes — documented in Key Decisions section above

### Issue: AI Improve Had No Awareness of Other Characters
- **Error**: No error — functional gap identified by user
- **Cause**: The `handleImproveBackstory()` function only used the character's own existing backstory as context; had no access to the rest of the cast.
- **Solution**: Added `otherCharacters` prop, context picker dropdown, and updated prompt construction to include selected character details + free-text extra context.
- **Learning Logged**: No formal learning file created; pattern matches existing "Describe Your Story" AI improve context pattern in Setup.tsx.

Browser auto-correction desync's React's virtual DOM, breaking event handlers on completely unrelated elements. React's DOM nesting warnings are actionable errors, not cosmetic warnings. Pattern to avoid: never use `<button>` as a collapsible container that holds other interactive children — use `<div role="button">` instead.
